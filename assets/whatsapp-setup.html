1. Connect the business account

Open Meta for Developers and sign in with the business owner’s account. Create or select a business app and open WhatsApp → API Setup. The owner must complete Meta sign-in and phone verification.

If you want to keep using the phone app, check the official existing-number/coexistence onboarding offered for your account or an eligible provider. 3. Approve the templates

Default language: en_US. Template bodies must use the positional variables below; URL button configuration must match the dynamic suffix passed by the website.

babyone_cart_reminder — Marketing

Hi {{1}}, your BabyOne bag is saved.
Items: {{2}}
Product subtotal: {{3}}. Delivery is calculated at checkout.
Review your items and complete your order below. Reply STOP to stop WhatsApp messages.

Body parameters: customer name, compact product/quantity summary, product subtotal. Include a “Complete your order” URL button. Its static URL base is https://babyone-web-test.up.railway.app/?; append one dynamic variable {{1}} for the signed recovery query. The website sends the query string without the initial question mark.

babyone_order_update — Utility

Hi {{1}}, here is your BabyOne order update.
Order: {{2}}
Status: {{3}}
Items: {{4}}
Order total: {{5}}
Use the button below to view your order. Reply STOP to stop WhatsApp messages.

Body parameters: customer name, order ID, status, product/quantity summary, recorded order total. Include a “Track order” URL button with static base https://babyone-web-test.up.railway.app/ plus dynamic suffix {{1}}. The website sends ?track=ORDER_ID. Keep promotional text out of the utility template.

If your approved template names/language differ, set WHATSAPP_CART_TEMPLATE, WHATSAPP_ORDER_TEMPLATE and WHATSAPP_LANGUAGE privately in Railway.

4. Configure the webhook

Callback URL: https://babyone-web-test.up.railway.app/api/webhooks/whatsapp. Use the matching verify token and subscribe to message/status callbacks. The server verifies X-Hub-Signature-256 using the app secret and checks the sender phone-number ID. STOP replies disable both message preferences.

5. Test before normal use

  1. Use a verified test customer who explicitly enables the desired WhatsApp choices in their account or checkout.
  2. Add products to the bag. After 20 minutes without changes, one reminder should be accepted. Changing/emptying the bag or placing an order cancels stale reminders.
  3. Check that the recovery link requires the matching customer's login, shows the complete current bag and recalculates checkout prices/delivery.
  4. Place a test order, then save each allowed fulfilment step. Each saved status queues one update.
  5. Check accepted/sent/delivered/read receipts in Dashboard → WhatsApp messages. “Accepted” is not a delivery confirmation. Uncertain sends pause instead of retrying blindly.
  6. Reply STOP and verify no additional automatic messages are sent.

Provider charges and message approval/delivery limits apply. The site does not send WhatsApp messages from a floating chat link alone.
